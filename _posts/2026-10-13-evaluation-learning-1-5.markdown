## 复习时优先采用的规则

| 容易混淆的问题 | 本次教学最终澄清 |
|---|---|
| 被测对象是否只能是纯模型 | 可以是生成组件、生成加后处理，或完整应用；关键是明确起止边界，结论不越界。 |
| 材料不足是否必须排除 | 不必须。即使不运行检索，也可测试生成组件的未知处理。 |
| 固定输入是否意味着没有历史 | 不。保留样本应有的问题、材料、历史、角色与顺序，只不继承前一次独立实验的新回答。 |
| P1/P2是否是两个模型 | 本课程中是同一模型的两种提示配置。 |
| 丁未提供evidence，为什么G仍为1 | 本课缺少引用字段本身归F；G检查主张支持与已有引用正确性。可另设引用完整性维度，但不能事后混用。 |
| G通过是否代表任务完成 | 不。材料充分时只说无法确定，可能C=0、G=1。 |
| 批次与重复轮次是否必须分开 | 不必须。批次若定义为全样本各跑一次，可以兼任重复轮次；编号需唯一且定义一致。 |
| 超时怎样评分 | 没有完整回答，C/G/F为N/A，状态timeout；仍进入全部计划运行分母。 |
| 人工修正怎样保留 | 原raw_output不变，关联新增corrected_answer等修正记录，不冒充新模型运行，不计模型通过率。 |
| 题本身错了怎么办 | 先修评测缺陷，版本化并复评；不能归咎模型。 |

这里的C/G/F规则是本课程用于教学的自定义分解，不是所有评测框架的统一定义。C为0/1/2，G/F为0/1；N/A不是0分。讲义正文保留原有内容，涉及上述歧义时以各课澄清与本表为准。

## 第一课：定义评测对象与边界

### 讲义正文

这节课只解决一个问题：怎样写清“本次测什么、不测什么，以及结果能说明什么”。先看完整示范，再做一个小练习，不要求重答整份试卷。建议用时约 30—40 分钟。

#### 一、第一性原理：把三个概念分开

**基石：**被测对象是接受测量的系统或组件；评测边界限定它在什么输入、功能和运行条件下被测；实验变量说明本次对比主要改变什么。三者不是同一件事。

以一个虚构图书馆制度问答助手为例，它的链路为：读者问题 → 检索借阅规则 → 组织提示与上下文 → 模型生成 → 格式校验 → 向读者展示答案。

如果问题是“助手是否能开放试用”，被测对象通常是完整问答链路。输入是读者问题，输出是最终答案或失败状态，检索、生成及格式校验都在对象内部。发现答错，只能先说应用失败，不能直接断言模型生成失败。

如果问题是“提示词 P2 是否比 P1 更好地避免无依据回答”，可以只测生成环节：给定问题和固定材料，将它们与 P1 或 P2 一起送入同一候选模型。被测对象是两种提示配置下的生成组件，改变的是提示词，检索不在本次对象内部。这不是纯粹测一个脱离配置的模型，也不是完整 RAG 评测。

生成环节实验中，固定材料既可以来自真实检索，也可以是人为构造的缺证据材料。不实际运行检索，不代表只能测材料充分的简单题。

**结论边界随对象改变。**生成环节表现好，只支持“给定这批材料时生成表现好”，不能证明检索能找到这些材料，更不能证明完整产品可以上线。

#### 二、逆向检查：为什么对象写错会误导结论

问题倒置：如果想把一个差产品评成好产品，就只测生成环节、给它完美材料，再把高分写成“产品可上线”。反推得到的要求是：报告中的结论必须对应实际测试的对象。

反事实：如果检索没有找到借阅例外条款，那么原本正确的生成组件也可能给出不完整答案。如果材料正确、最终展示却把引用截断，那么问题可能在后处理，不能仅看生成原文。

对立视角：读者未必关心模型与检索谁出错，他们只关心最终回答是否误导自己。这要求产品试用决策关注完整链路；研发人员则需要组件测试定位问题。两个视角都合理，但回答的不是同一个问题。

反向试错：对象只写“模型” → 补清是否含检索与后处理；输入只写“相关问题” → 列出实际覆盖的语言和任务；排除所有材料不足问题 → 加入未知情况处理测试；组件高分被写成产品高分 → 明确结论适用范围。

#### 三、完整示范：为提示词对比定义边界

假设研发团队正在选择 P1 与 P2，暂时不评估图书馆助手是否可以开放试用。两种提示使用同一模型，只改变对材料不足时如何作答的指令。以下是教学假设，不是现实图书馆规定。

##### 一份可以执行的定义

决策：选择哪种提示配置进入下一阶段的完整应用测试。本课先定义测试范围，具体通过门槛在后续课程讨论。

被测对象：同一候选模型在 P1、P2 两种提示配置下的单轮生成组件，包括最终回答的格式检查；不实际运行检索，不执行借书或续借操作。

输入边界：中文文本的借阅制度问题，以及一组预先固定的规则片段。题目覆盖借阅期限、续借条件、例外条款、材料不足及条款冲突。多轮历史、图片、语音和实时账户信息不在本次覆盖范围内。

输出边界：返回包含“结论”和“依据”的约定结构，或记录生成超时及格式失败状态。超时不能被静默删除。材料不足时如何表达，属于生成质量评测，而不是排除该题的理由。

功能边界：测制度解释及未知情况处理，不测账户余额查询和实际续借执行。若用户要求“替我续借”，不评价续借操作是否成功；可以另外测试助手是否清楚说明无法执行。这里必须区分“某功能不在范围内”和“越界请求如何处理是否被测”。

运行条件：同一候选模型标识、同一批问题和材料、相同输出预算与超时策略，记录采样设置；只改变 P1/P2。无法确认的版本或参数写未知，并在结论中说明限制。

结论边界：本次可以比较两种提示在固定材料、指定任务与配置下的生成表现；不能评价真实检索质量、端到端延迟、账户权限或完整产品试用资格。

##### 怎样检查定义是否真的完整

让另一个人只看定义，判断三个输入如何处理：“按给定条款解释续借条件”属于范围内；“给定片段没有续借条件”仍可属于范围内，因为要测未知处理；“访问我的账户并完成续借”不属于动作执行范围。

如果对方还必须追问“材料哪里来、是否运行检索、是否允许联网、超时算什么、结论测到哪里”，说明定义仍有空缺。

##### 概念上的取舍

先测组件的优势是变量容易控制，适合定位提示词问题；局限是不能代表完整链路。适用前提是决策本身就在选择提示或诊断组件。

先测完整应用的优势是贴近用户结果；局限是失败不容易直接归因，需要保存检索和生成等阶段记录。适用前提是要做应用选型或试运行判断。

两种方式不是二选一的长期策略，可以先做完整链路测试发现问题，再用组件测试排查，修复后回到完整链路做回归。

#### 四、你的迁移练习

给定任务：企业员工制度问答助手出现错误回答，团队怀疑“检索片段已经足够，但生成环节没有遵循材料”。这只是待验证假设。现在需要比较提示词 P1 与 P2，不是决定完整助手能否试运行。

请独立回答下面四题，每题约 2—4 句话，不要求写指标或阈值：

1. 本次被测对象是什么？你会如何取得、固定并核验输入材料，使实验能检验上述假设，而不是预先认定假设为真？
2. 检索、生成、后处理分别是否进入本次对象边界？为什么？
3. 对材料不足、资料冲突和多轮追问，你准备纳入还是排除？分别说明理由；至少纳入一个困难场景。
4. 如果 P2 在这次实验中表现更好，你能得出什么结论，又不能得出什么结论？

练习完成标准：别人能判断你是否真正运行检索、输入材料如何获得、哪些困难样本仍在范围内、结论为什么不能直接支持产品试运行。具体答案等你提交后再讲，不在本讲义预设。

建议：先写自己的边界定义，再对照示范检查，不直接把“图书馆”替换成“员工制度”。预期效果是从复述模板转向解释取舍；代价是需要主动思考，但比提前背验收答案更能检验理解。

脑暴：把组件评测看作单元测试、应用评测看作集成测试，可以帮助复用开发经验。但语义回答通常需要人工标准和重复观察，不能完全照搬确定性程序测试。

下一课将讨论“从质量要求到评分标准”：例如怎样把“不要编造”转换为可以逐题判断的要求。先把这四题发回，我们用反馈确认对象与边界的理解，再进入下一课。

### 作答、批改与追问记录

#### 1. 四道迁移题的原始答案

题目背景：团队怀疑检索片段已经足够，但生成没有遵循材料；这是待验证假设。现在比较提示P1/P2，而非决定整个助手能否试运行。题目分别要求定义对象和材料核验，决定检索/生成/后处理边界，选择材料不足/冲突/多轮场景，并限定结论。

原始答案：

```text
1. 被测对象还是生成组件。通过人工查看检索过程文件，评估材料的全面程度，从而确认前提是否满足，即「检索足够」这个条件是否为True
2. 检索和后处理不应该进入本次对象边界。被测对象是生成组件，所以前置的检索环节不应该纳入评测，同理，后处理也与生成本身无关，评测过程需要围绕被测对象来进行。
3. 材料不足不纳入，这个属于前置检索环节。条款冲突纳入，在检索材料足够的前提下，是存在条款冲突的场景，本身会影响生成的结果。多轮追问也可以纳入，我的理由同样影响生成结果。
4. 在当前检索条件下（此时还不知是否充足），P2的生成组件表现更好。不能说P2时助手的表现好，需要关注边界和被测对象。
```

批改整理：对象与结论不越界的方向正确。人工查看实际检索记录是证据线索，但只看检索到的片段，不能知道遗漏了什么；应对照适用的权威原文，逐题核验必要条款是否完整，再冻结输入。第一题确认充足与第四题尚不知充足需要统一。

后处理排除是合理选择，但不是唯一规则；也可以定义生成＋格式校验为组件。不是因为它不属于生成就天然不能测，而是应提前说明范围。

材料不足来自上游，不代表生成兜底不能测。可以因本次只诊断充分材料下的错误而排除，但要披露这个局限。条款冲突可纳入；多轮若纳入需固定历史，不能只因影响生成就无限扩范围。

结论应写为在这批固定材料与相同配置下P2表现更好。材料已核验充分时可加这个限定，未核验不能预设其充分；不能代表完整助手试运行资格或生成的全部能力。

#### 2. 对实验范围的补答

补答题：选择仅材料充分或同时含材料不足，说明理由、怎样固定P1/P2输入，以及结论不能覆盖什么。

原始答案：

```text
本次实验选择同时包含材料不足。优势在于可以覆盖生成组件对于原始材料不足的兜底处理，评估其稳健性。多次实验中，需要确保P1P2输入的检索结果和上下文一致，怎么做我没理解，等会你给我讲讲。最终结论无法覆盖整体助手的表现，只能说明生成组件的能力
```

批改整理：范围选择合理；覆盖正常回答与兜底。最后一句应收窄为在这批样本和配置下的生成表现，不能泛称组件全部能力。

输入固定的教学补充：先检索一次并保存结果，同一份问题、材料及历史交给两边，只替换提示。P1/P2提示本身不同，所以全部上下文不会字面完全相同。多次独立重复重新加载同一样本，不追加上次实验回答；参考要点只交给评分者。原对话还提出五条片段与十条片段是否只比较提示词的检查题，未见你单独作答，不补写答案记录。

#### 3. 追问：生成前已有历史检索结果能否覆盖

你的原始追问：

```text
生成前如果有上下文呢？比如之前的检索结果，这种场景不能覆盖么
```

答复整理：可以覆盖。保持一致不是要求没有上下文，而是两边面对同一份已有状态。保存前轮问题、实际保留的检索结果、前轮回答、当前问题和当前检索结果，再分别运行P1/P2；内容、顺序、消息角色和截断规则一致。只保留真实系统会送入模型的内容，不额外添加实际不存在的历史片段。

固定历史比较本次生成，适合归因；让两边从头运行多轮、各自检索生成也合理，但测试对象成为完整对话过程，历史不同是运行结果的一部分，不能仅解释为当前一轮提示差异。

#### 4. 阶段性反馈

你随后询问能否进入下一课。反馈为可以：已掌握对象、困难场景纳入及结论边界；固定输入的实操可继续巩固。阶段性通过不等于第一周综合验收通过。

## 第二课：从质量要求到评分标准

### 讲义正文

本课目标：把“回答正确、不要编造、格式规范”转换成另一名评分者也能执行的规则。沿用上一课的对象：固定问题、材料和历史，只比较 P1/P2 的原始生成结果。今天不讨论上线阈值，不先计算综合总分。建议学习与练习约 30—40 分钟。

#### 一、第一性原理：质量要求不是评分标准

**基石：**评分标准需要说明检查什么、依据什么、怎样得分，以及遇到边界情况如何处理。

“不要编造”是愿望；“逐条检查回答中的制度主张，存在任一不能由提供材料支持的主张，就将有据性记为 0”才是可以执行的规则。

| 环节 | 要回答的问题 | 示例 |
|---|---|---|
| 质量要求 | 希望模型做到什么？ | 回答正确，不编造 |
| 评分维度 | 分别检查什么？ | 核心答案正确性、有据性、格式合规 |
| 判定依据 | 对照哪份证据？ | 经核验的参考要点、实际提供材料、输出约定 |
| 判分规则 | 满足到什么程度得几分？ | 完整正确得 2 分，部分正确得 1 分，错误得 0 分 |
| 评分锚点 | 哪些具体回答代表不同分数？ | 一份得 2 分的回答与一份得 1 分的回答 |

Rubric 就是评分维度、分档规则和边界约定组成的评分说明。参考答案不必是一句固定文字，也可以是必须覆盖的要点及允许表达。“部分正确”如果没有定义，仍然容易引发分歧。

#### 二、逆向检查：防止标准奖励错误行为

问题倒置：怎样让糟糕回答获得高分？只检查格式，或者只检查有没有编造，却不检查是否回答了问题。反推得到的要求是：任务完成与有据性要分别观察。

反事实：如果模型遇到任何问题都说“无法确定”，它可能没有编造，却没有完成材料充分的任务。如果答案正确但引用与答案无关，仅凭正确结论也不能判定依据合格。

对立视角：员工关心能否采取正确行动，开发者可能更关注 JSON 能否解析。两者都重要，但格式通过不能抵消错误的制度结论。

反向试错：分档写“优秀/一般/差” → 改成可观察条件；标准只奖励拒答 → 检查是否存在可以回答的要点；先看结果再改标准 → 先定版本，修订后重新评分；把格式失败当成内容错误 → 分开记录维度；只出总分 → 保留各维度与失败原文。

#### 三、完整示范：报销制度问答

以下制度全部虚构，只用于教学。假设材料已经人工核验为本次有效版本。

R1：单笔报销金额不超过 500 元时，只需直属主管审批。

R2：单笔报销金额超过 500 元时，需直属主管和财务共同审批。

实际送入模型的材料仅有 R1、R2，没有到账时限条款。没有条款不代表现实中没有时限；它只表示这份输入不足以支持确定时限。

示范问题：“我有一笔 600 元的报销，需要哪些人审批？”

参考要点：“直属主管和财务共同审批。”允许同义表达。参考要点只交给评分者，不作为被测模型输入。

##### 一份最小评分标准

本课的评分单位是一条问题对应的一份完整回答，三个维度分别记录，不直接相加。

| 维度 | 判定依据 | 规则 |
|---|---|---|
| 核心答案正确性 C | 题目要求与经核验的参考要点 | 2：全部必要要点正确；1：部分必要要点正确且没有错误核心结论；0：任一核心结论错误，或没有回答任何必要要点。 |
| 有据性 G | 实际提供的材料，以及必要时用于核验引用的原文 | 1：所有制度事实主张都有材料支持，引用对应正确；0：至少一个制度主张无依据、与材料矛盾或引用不支持该主张。 |
| 格式合规 F | 预先定义的输出约定 | 1：符合下述 JSON 契约；0：不符合。 |

格式契约：输出必须整体是一个可解析 JSON 对象，恰有 `answer` 与 `evidence` 两个字段；`answer` 是非空字符串；`evidence` 是字符串数组，可以为空；数组非空时每项只能是 R1 或 R2。不能在 JSON 前后添加寒暄或 Markdown 代码围栏。这里只检查结构和编号是否合法，编号是否真正支持结论由 G 判断。

边界约定：C 只评价题目要求的核心要点；题外新增的制度主张由 G 检查。如果新增内容同时改变或否定核心答案，C 也受影响。这是本课为了便于定位错误采取的自定义拆分，不是所有评测系统都必须采用的通用定义。

未知处理约定：当必要输入确实不足时，明确说明无法确定及缺少什么属于正确要点；当材料足够时，笼统说无法确定不属于正确答案。对没有制度事实主张、仅笼统拒答的回答，G 可以通过，但 C 可能为 0，因此有据性不是任务完成率。

##### 评分锚点

以下回答均为人工构造的教学例子，不是实测模型输出。单行展示的 JSON 表示原始回答本身，不包括外层代码围栏。

A：`{"answer":"需直属主管和财务共同审批。","evidence":["R2"]}`

C=2、G=1、F=1。核心要点完整，引用对应，格式合规。

B：`{"answer":"需要直属主管审批。","evidence":["R2"]}`

C=1、G=1、F=1。“主管需要审批”受 R2 支持，但没有回答完整的审批人名单。这里没有使用“只需主管”；若写“只需主管”，就否定了财务审批，C=0、G=0。

C：`{"answer":"需直属主管和财务共同审批，审批后保证三天到账。","evidence":["R2"]}`

C=2、G=0、F=1。题目只问审批人，核心答案完整，但新增到账保证没有依据。因此这份回答不能算整体合格，不能因为 C 满分而忽略 G。

D：“需直属主管和财务共同审批，依据 R2。”

C=2、G=1、F=0。内容有依据，但不是约定 JSON。

E：`{"answer":"无法确定。","evidence":[]}`

C=0、G=1、F=1。没有新增制度事实，但材料已经足够，未完成任务。若它写“材料没有规定审批人”，这又与材料矛盾，G 也应为 0。

这组锚点说明三个维度不能互相替代，也不保证统计独立。同一个错误核心结论可能同时导致 C、G 失败。

##### 如何处理有争议的回答

先保存原文，再指出是哪一条规则不清楚；讨论后修订 Rubric 版本，并用新版本复评受影响样本。不要为某个模型的回答临时开特例。本课先采用简单分档，优势是便于核对，局限是无法精细衡量每个错误的严重程度；复杂等级和业务门槛留到后续再学。

格式判断通常先用解析器及字段校验，规则明确、便宜且可复现。开放语义先做人工评分，代价是需要校准；规模扩大后可引入模型裁判，但它必须遵守同一标准并与人工核对。评分器选型发生在标准定义之后，而不是用评分器替代标准。

#### 四、你的练习：先判分，再解释

仍然只提供上面的 R1、R2。现在的问题是：“一笔 400 元的报销需要谁审批？审批通过后多久到账？”

作答前请先写出你认为必要的回答要点，再使用本课的 C、G、F 规则给以下四份回答评分。练习不提供分数答案。

回答甲：`{"answer":"只需直属主管审批；材料未规定到账时限，无法确定。","evidence":["R1"]}`

回答乙：`{"answer":"需直属主管和财务共同审批，三天内到账。","evidence":["R1"]}`

回答丙：`{"answer":"只需直属主管审批。","evidence":["R1"]}`

回答丁：“只需直属主管审批。现有材料未规定到账时限，无法确定。”

请按“回答名称；C/G/F 分数；扣分或通过对应的原文；所依据的判分规则”回复。之后再回答一个设计题：如果助手每次都说“无法确定”，为什么只看有据性会误判它的表现？

本课完成标准：能分别判断核心要点、有据性和格式，能解释遗漏与错误的区别，能正确处理材料不足而不鼓励一律拒答。不要求写代码，不要求设计上线总分。

建议：先独立评分，再提交分歧点。预期效果是检验规则能否指导真实判分；代价是需要逐句查看，但比只记住“正确性、幻觉率”更扎实。

脑暴：把 Rubric 当作评分者之间的接口契约。目标不是保证没有分歧，而是让分歧能被定位、讨论和修正。

下一课可进一步讨论样本设计：怎样用常规、边界和材料不足问题检验这份标准，而不是只挑容易得高分的题。

### 作答、批改与追问记录

练习题背景：提供R1、R2，问400元报销由谁审批以及审批后多久到账。甲同时正确回答可知与未知；乙增加财务审批并编造三天到账；丙只答审批人；丁正确作答但没有JSON。题目原文及四份回答见前面的完整讲义。

#### 1. 甲、乙、丙的原始评分

```text
甲：C=2, G=1, F=1
乙：C=0, G=0,F=1
丙：C=1, G=1, F=1
```

批改整理：三份都正确。甲必要要点完整；乙两项制度主张错误或无依据，但格式合法；丙遗漏到账问题，C部分分，已说出的内容有据，G通过。遗漏不自动等于编造。

#### 2. 丁的原始评分与纠正

```text
丁：C=2,G=0,F=0
```

批改整理：应为C=2、G=1、F=0。审批人结论受R1支持，到账时限未规定的表述也符合实际材料。丁没提供JSON和evidence字段属于格式失败，不是主张无依据。

你的原始追问：

```text
对于丁，答案与材料一致就可以给到G=1对吗？不需要关注是否在evidence中给出么？
```

后续澄清：本课G检查主张能否由材料支持、已有引用是否真正支持主张；是否存在规定的evidence字段归F。缺少引用不直接扣G，提供错误引用则扣G。实际项目可另设引用完整性，但必须提前写明，不事后改变判分。此前引用对应正确的措辞未充分说明缺失引用，属于讲解需要补充的边界。

#### 3. 为什么一律拒答会被G高估

你的原始答案：

```text
助手每次说「无法确定」时，不管材料是否可以支持答案，至少不会因为「引用错误」、「引用无依据」、「与材料矛盾」等原因扣分。存在错误答案但不扣分的场景，所以会存在高估的可能性。
```

批改整理：核心理解正确。更准确地说，是未完成任务但能通过有据性，而不是所有错误答案不扣分。材料充分时笼统说无法确定，可C=0、G=1；若说材料没有规定审批人，而材料实际已经规定，这个事实主张与材料矛盾，G也为0。一律拒答不是必然通过G。

阶段性结论：第二课通过。已能区分错误、遗漏、无依据主张和格式问题。

## 第三课：如何设计评测样本

### 讲义正文

本课只解决一个问题：怎样设计样本，让模型的正常回答、边界判断与未知处理都能被检验。沿用前两课的范围：评测固定材料下的生成组件，比较 P1/P2，不实际运行检索。建议用时约 30—40 分钟，不要求编程。

#### 一、第一性原理：样本不是只有一道问题

**基石：**一道评测样本需要同时固定“模型看到了什么”和“评分者据什么判断”。相同问题配上不同材料，可以构成不同样本。

| 部分 | 保存内容 | 用途 |
|---|---|---|
| 模型输入 | 当前问题、实际提供材料、对话历史及消息顺序 | 重现回答条件，供 P1/P2 配对比较 |
| 判定依据 | 经核验的必要回答要点、依据、可回答程度 | 支持上一课的 C/G 判分，不发送给模型 |
| 管理信息 | 样本编号、类别、设计目的、来源、关联组及版本 | 追溯样本，分组分析，管理近似题 |

提示词版本、模型及输出契约可以统一记录在实验配置中，不必在每题重复全文，但必须能追溯。评分时 F 对照实验中预先约定的格式要求。

参考要点不是要求逐字照抄，而是必须回答的结论、条件或无法确定之处。本课“正确行为”的依据是给定材料：输入不足时，即使模型猜中了现实规定，也不满足只依据材料作答的任务要求。

最简单的设计方法是：从一个想检查的失败出发，选择能暴露它的问题和材料，再先写参考要点。不要先看模型回答，再决定什么算正确。

#### 二、逆向检查：题量不等于覆盖

问题倒置：怎样制造一个漂亮却无用的评测集？只出最容易的题，或把一道题改写几十遍，再把高分解释为能力全面。反推得到的要求是：每题都应说明它检查的行为或失败类型。

反事实：如果所有题都缺材料，一律说无法确定的模型可能成绩很好。如果所有题都有完整材料，又无法知道模型遇到证据缺口时是否编造。样本集要同时检验“该答时答”和“不该确定时不确定”。

对立视角：开发者可能偏好规则明确、容易评分的题；员工却可能一次询问多个条件。样本中应保留混合问题，检验助手会不会只答一半，或把已知部分也一起拒答。

反向试错：样本有歧义但参考答案强行唯一 → 补足输入或允许澄清；同模板换数字充当独立证据 → 标记关联组；只有容易题 → 加边界与缺材料；参考答案未经核验 → 先人工检查；看到失败就删题 → 保留失败并调查是否是评测缺陷。

#### 三、完整示范：从规则到样本

仍使用虚构报销规则，不是现实企业或法律规定：

R1：单笔报销金额不超过 500 元时，只需直属主管审批。

R2：单笔报销金额超过 500 元时，需直属主管和财务共同审批。

没有到账时限规则。下面所有样本都是中文单轮，历史为空。R1＋R2 表示给模型提供两条规则全文，顺序固定；仅 R1 表示确实不提供 R2。参考要点只给评分者。

| 编号 | 问题 | 实际提供材料 | 必要回答要点 | 设计目的 |
|---|---|---|---|---|
| S01 | 一笔 300 元报销需要谁审批？ | R1＋R2 | 只需直属主管 | 常规：是否正确使用低金额规则 |
| S02 | 一笔 600 元报销需要谁审批？ | R1＋R2 | 直属主管和财务共同审批 | 常规：是否完整列出审批人 |
| S03 | 一笔恰好 500 元报销需要谁审批？ | R1＋R2 | 只需直属主管 | 边界：是否把“不超过”理解为含等于 |
| S04 | 一笔 500.01 元报销需要谁审批？ | R1＋R2 | 直属主管和财务共同审批 | 边界：是否识别刚超过门槛；教学假设金额可精确到分 |
| S05 | 一笔 600 元报销需要谁审批？ | 仅 R1 | 无法确定；缺少超过 500 元的适用规定 | 材料不足：会不会擅自补全未提供规则 |
| S06 | 一笔 300 元报销需要谁审批？审批后多久到账？ | R1＋R2 | 只需直属主管审批；材料未规定到账时限，无法确定 | 部分可回答：能否分开已知与未知，而非只答一半或全部拒答 |

S02 与 S05 的问题相同，但材料不同，所以是两道不同样本。S02 需要明确回答，S05 需要说明不足。这对样本可以检查模型是否真正依赖输入证据，而不是背出同一个答案。

S03 与 S04 是边界对照：只改变金额，适用规则和答案应随之改变。如果两题都回答相同，就暴露边界判断问题。

这些是配对探针，不是控制所有变量的普遍因果证明。S02/S05 之间有意改变材料来设计不同测试状态；在每个状态内部，P1/P2 必须接收同样的材料，只改变提示词。

##### 把一题写成完整样本记录

以 S05 为例：编号为 S05；问题原文固定为“一笔 600 元报销需要谁审批？”；材料是 R1 全文；历史为空；参考要点是“现有材料不足以确定，需要超过 500 元的规定”；可回答程度为不可确定；主类别为材料不足；设计目的为检查无依据补全；来源为人工构造的虚构规则；关联组为“600元审批配对”；数据及评分版本另行记录。

这里的“不可确定”是相对于本样本的输入，不是说现实中没有规则。评分者知道 R2，不代表模型也看到了 R2。不能把参考要点或未提供的 R2 偷放进模型上下文。

##### 怎样核验样本本身

运行模型前，人工检查问题与材料是否对应、参考要点能否成立、例外和适用条件是否遗漏、是否需要补充信息，以及题目是否确实在生成组件范围内。请另一名评分者核验更可靠；没有第二人时，也应逐条回看依据，而不是直接采用模型生成的参考答案。

“600 元需要谁审批”可以因缺条款而不可确定；“我这笔报销需要谁审批”可以因缺金额而无法确定，后者可要求澄清。信息缺口来自哪里，也应记录，这有助于分析不同失败。

##### 怎样扩成一个小型评测集

先围绕覆盖目的增加样本，而不是立即追求 30—50 题。初学时，可以设计 8 道诊断题：常规 2 道、边界 3 道、材料不足 2 道、部分可回答 1 道。每题指定一个主类别，额外标签可以重叠。这是教学配比，不代表实际员工问题的分布，也不是规定的最低题量。

优势是覆盖清楚、容易定位错误；局限是人工设计可能偏离真实业务。以后从经授权、脱敏的实际问题中抽样，用自然分布样本了解日常表现，再单独报告边界与高风险诊断集。不要把刻意增加的困难题当成真实流量占比。

分别报告常规、边界和未知处理表现，避免一律拒答或只擅长容易题的模型被平均分掩盖。小组样本很少时，写出题数与具体失败，不给出总体能力结论。

##### 今天的样本能否直接做保留测试集

本课示范及你用来练习、校准和修改提示词的样本属于开发材料。它们能发现问题，但不能再称作未使用的保留测试集。

同问题的充分/不足版本、同模板的近似改写应记录为关联组，未来切分时避免组内近似题跨开发与保留集合。共享业务文档本身不必然是泄漏：RAG 本来就可能使用同一知识库。要防的是按保留问题及答案反复调优，以及近重复样本造成的虚高。八题教学练习不要求现在强行切分，后续再独立构建并封存保留题。

#### 四、你的练习：设计三道新样本

使用上面的 R1、R2，不改企业规则，不另选场景。请设计三道单轮样本：一道金额边界题，一道信息不足题，一道部分可回答题。

边界题不要直接照抄 S03/S04；可以换一种日常问法，但仍要真正检验门槛，不能只把 300 改成 400。当金额门槛只有一个时，复用该数值合理，重点是能解释设计目的。

信息不足题请明确缺的是制度条款还是用户条件。部分可回答题应包含至少一个能回答的要点和一个不能确定的要点。

每题提供以下内容：样本编号、问题原文、实际提供材料全文、历史、必要回答要点、可回答程度、设计目的，以及这题与其他样本是否属于同一关联组。不要生成模型答案或预设模型得分。

最后解释：如果这三题全部通过，为什么仍不能认为生成组件普遍可靠？

本课完成标准：问题、材料和参考要点一致；边界题能暴露门槛误读；缺材料时不把未提供制度当成模型应知；混合题明确区分可答与不可答部分；承认小型诊断集的局限。先提交样本，我们核验题本身，再谈跑模型。

建议：每题先写“我想检查哪种失败”，再写输入和参考要点。预期效果是避免只换措辞凑题量；代价是设计速度较慢，但更容易解释每题为何存在。

脑暴：把每道题看成一个探针，测不同条件下的行为。探针覆盖需要人工设计，真实场景分布则需要业务数据支持；两者互补，不能互相冒充。

下一课可以学习如何组织和运行样本：将经过核验的样本保存为 JSONL，保留逐题结果，并分开汇总不同类别表现。

## 第四课：组织与运行可追溯评测集

### 讲义正文

本课目标：把上一课的样本组织成可重跑、可复评的实验，避免只留下一个分数。继续评测固定材料下的生成组件，不要求搭建检索系统、安装评测框架或购买 API。建议讲解与练习约 30—40 分钟。

#### 一、第一性原理：四类记录不能混为一谈

**基石：**样本告诉我们测什么，配置告诉我们怎么测，原始结果告诉我们发生了什么，评分告诉我们怎样解释它。

| 记录层 | 最少保存内容 | 用途 |
|---|---|---|
| 样本 | 编号、类别、问题、实际材料、历史、参考要点、版本 | 固定任务，支持配对比较 |
| 实验配置 | 配置编号、提示全文、模型标识、生成参数、数据与 Rubric 版本 | 解释差异，定位实际变化 |
| 原始结果 | 样本及配置编号、重复轮次、请求状态、原始文本、异常 | 保留真实行为，不用分数代替原文 |
| 评分 | 原始结果编号、C/G/F、判分理由、评分者、Rubric 版本 | 修改标准后无需重新生成即可复评 |

四类记录可以在一个文件的不同区域，也可以分开保存。关键是逻辑分离，不是必须创建四个文件。评分修改后保留旧版本，不覆盖原始回答。

#### 二、逆向检查：没有原始结果会发生什么

问题倒置：怎样把不可靠系统统计得很好？删除超时题、把格式错误修好再评分、反复重生成直到满意，只留下最后的总分。反推得到的要求是：保存原始文本、失败状态与尝试记录，并提前确定重试策略。

反事实：如果 Rubric 改了但原始回答还在，可以重新评分；如果只剩分数，只能重新运行，而新回答未必与旧回答相同。如果格式解析失败但回答文本仍然完整，语义可能正确，不能直接把 C、G 记为 0。

对立视角：员工在意请求是否得到可用回答，研发人员还要知道问题出在传输、格式还是语义。因此“请求返回率”与“内容正确率”回答不同问题，应分别报告。

反向试错：没有样本编号 → 无法逐题对齐；只保存解析后的 JSON → 丢失格式失败证据；删除超时 → 分母虚高；将参考要点整条送入模型 → 答案泄漏；看到结果才决定怎样重试 → 引入结果选择偏差。

#### 三、完整示范：样本到实验记录

##### 1. 把样本写成 JSONL

JSONL 是每行一个完整 JSON 对象。它与一个大 JSON 数组不同，通常便于逐条读取与追加结果。下面只是讲义中的样例，不要求现在写程序。

沿用虚构制度：R1 为不超过 500 元只需直属主管审批；R2 为超过 500 元需主管和财务共同审批。以下样本的问题是 600 元报销，但实际只提供 R1。

```json
{"id":"002","category":"材料不足","input":{"question":"一笔600元报销需要谁审批？","context":[{"id":"R1","text":"单笔报销金额不超过500元时，只需直属主管审批。"}],"history":[]},"reference":{"required_points":["现有材料无法确定审批人","缺少超过500元的适用规定"]},"dataset_version":"d1"}
```

整行存入评测数据不代表整行发给模型。构造请求时，只选择 `input` 内的问题、材料和历史，再加入对应提示。`reference`、类别和设计目的属于评分或管理信息，不作为模型输入。

对其他金额题，应各自保存真实材料全文，而非只有“R1＋R2”的缩写。如果通过材料编号引用外部文件，必须能还原版本和顺序。

##### 2. 保存配置，而不只保存 P1/P2 名称

为演示控制变量，给出两段提示内容。它们只用于教学开发，不作为保留测试材料。

P1：“根据提供材料回答当前问题。输出整体为 JSON 对象，仅包含 answer 和 evidence；answer 是非空字符串，evidence 是引用编号的字符串数组。不得添加其他文字。”

P2：完整沿用 P1，再增加：“只使用提供材料；不能确定的部分明确说明无法确定及缺少什么；能回答的部分仍须回答。”

两边固定同一候选模型、同一样本版本、相同消息顺序、参数、输出预算和工具状态；只改变提示。记录实际提示全文或可恢复的版本，不能只写“P2”。这些提示不是最佳方案保证，需要通过评测观察。

不使用 API 时可以在同一聊天产品的独立新会话运行；可见设置保持相同，未知项写未知。不要声称这种实验严格可复现，也不要在本次课中擅自修改全局工具或记忆设置。

##### 3. 建立运行计划，给每个结果唯一身份

例如，3 道题 × 2 种提示 × 每题 2 次独立重复 = 12 次计划运行。每次使用相同样本重新开始，不把上一轮实验的回答追加到下一次；如果样本本身有固定历史，则每次仍应携带该历史。

原始结果身份可以由“批次、样本、配置、重复轮次”共同确定。这里 `repeat` 是计划中的独立重复，不是失败重试。

```json
{"response_id":"run01-002-P2-1","run_id":"run01","sample_id":"002","config_id":"P2","repeat":1,"request_status":"returned","raw_output":"{\"answer\":\"现有材料无法确定，需要超过500元的适用规定。\",\"evidence\":[]}","error":null}
```

正式请求还可以记录起止时间、可见 token 数和实际生成设置。无法取得的数据记 null 或未知，不用字符数冒充精确 token 数。

本课先不重试。以后需要重试时，预先规定次数及失败类型，保存每次 attempt，并说明怎样选定一次计划运行的最终结果；不得仅因语义答案不好就重试。并发与成本统计留到编程课，不需要今天实现。

##### 4. 将请求状态与格式状态分开

`request_status=returned` 只表示取得了一份完成的回答文本，不表示 JSON 或语义合格。超时等无法取得完整回答的状态单独记录；本课不将超时残留的部分文本当作完成回答评分，但可保留用于诊断。

格式解析失败时，仍保存原文，F=0。如果原文足以判断语义，人工照常评 C/G；若回答确实不可读、无法判定，记录待判定或 N/A，并在汇总中披露评估覆盖，不默认算正确。

没有回答的超时，C/G/F 均为 N/A。它不通过本次任务完成检查，但不能据此认定模型说出了错误内容。政策拒答若有完整文本则属于 returned，之后按任务标准判断是否正确，而不是自动当传输失败。

##### 5. 看一个完整统计示例

继续采用上一课 C=0/1/2、G=0/1、F=0/1。未给引用字段本身只影响 F；已有错误引用或无依据主张影响 G。以下四条记录全部是人工构造的教学结果，不是实测成绩。

| 计划运行 | 样本与原始输出概况 | 请求状态 | C | G | F |
|---|---|---|---:|---:|---:|
| 1 | 常规：300元，完整材料；正确回答只需主管，引用R1，JSON合规 | returned | 2 | 1 | 1 |
| 2 | 材料不足：600元，仅R1；擅自回答主管和财务，引用R1，JSON合规 | returned | 0 | 0 | 1 |
| 3 | 边界：500元，完整材料；原文“只需直属主管审批，依据R1。” | returned | 2 | 1 | 0 |
| 4 | 部分可答：300元审批人＋到账时间，完整材料；超时未取得完整回答 | timeout | N/A | N/A | N/A |

这里有 4 次计划运行，返回 3 份完整回答，正确核心答案 2 份，格式合规 2 份，三维同时通过只有第 1 份。

| 指标 | 计算结果 | 回答的问题 |
|---|---|---|
| 请求返回率 | 3/4=75% | 计划请求中多少取得完整回答？ |
| 已返回回答的核心正确率 | C=2 的回答数 / returned 数 = 2/3 | 已返回回答有多少核心答案完整正确？ |
| 已返回回答的格式合规率 | 2/3 | 返回回答有多少符合格式？ |
| 已返回回答的三维同时通过率 | 1/3 | 返回回答有多少同时满足 C=2、G=1、F=1？ |
| 按全部计划运行的任务通过率 | 1/4=25% | 包含运行失败后，有多少完整完成本课规定任务？ |

只有一题出现格式错误，但这份答案内容正确；超时也没有被偷偷移出全部计划运行分母。不要把 2/3 单独称为整个系统的“正确率”，必须写明口径。

表中所有 returned 回答都能人工评语义。若部分不可判定，应另外列“可判定数/返回数”和“正确数/可判定数”，并保留全计划任务通过口径；不能把未知样本无声删除。如果 returned 为 0，相应条件指标不可计算，全部计划通过率仍可报告为 0/计划数。若根本没有计划运行，则不计算比例。

按类别同样报告通过数和分母，重复轮次与不同样本数分别记录。三道样本重复十次仍是三道独立设计的样本，不变成三十个覆盖场景。单题类别不能用于推断业务总体表现。

##### 6. 保存评分，不改原始结果

评分记录引用 `response_id`，另外保存 Rubric 版本、C/G/F、判分理由和评分者。修改评分标准后新增一个版本的评分，不覆盖原始生成文本；这样可以不再次调用模型就复评。

先用人工记录或普通文件的优势是透明、容易理解；局限是规模变大后容易漏记录和对错编号。理解这些记录后再引入 Python 或实验管理平台，自动化的是同一流程，不是用工具替代规则。

#### 四、你的练习：先组织记录，不急着调用模型

承接你上一课的样本：001为499.99元审批；002为审批后到账时限；003为300元审批人＋提交材料。记得修正003参考要点为“主管审批；提交材料要求无法确定”，不是到账时间。

请独立完成四项：

1. 将002写为一条完整 JSON 样本，区分模型输入、参考要点和管理信息。明确说明构造模型请求时会选哪些字段，不会选哪些字段。
2. 为3道题、P1/P2、各2次重复设计结果编号，并说明怎样固定每次输入。无需实际运行12次。
3. 假设一条返回正确内容但不是JSON，另一条完全超时。分别说明会怎样保存请求状态、原始输出和C/G/F；不要提前虚构实际模型成绩。
4. 你已经保存原始回答后，发现Rubric需要修改。哪些记录应该保留，哪些记录需要新版本？为什么不一定需要重新调用模型？

可用文字或JSON回答，不要求提交程序。本课完成标准：参考答案不进入模型；编号能对齐样本、配置和重复；返回、格式与语义状态区分清楚；运行失败没有被删除；评分可以独立复评。

建议：先完成这四项结构练习，再选择手工跑一个小批次。预期效果是提前消除记录和分母错误，代价是短期不追求规模，但比跑完后无法解释成绩更稳妥。

脑暴：把原始生成结果视为不可修改的实验观测，把评分视为可版本化的解释。同一批观测可以在新标准下复评，但更换模型、提示或输入属于新实验。

下一课可以据此编写一个最小 Python 评测器：先读取预先保存的回答做格式校验与汇总，不依赖真实 API，也不需要部署大模型。

### 讲义正文

本课把第四课的记录流程转换成可运行程序：读取保存的回答 → 验证记录 → 校验输出格式 → 合并人工评分 → 保存逐题及汇总结果。不生成回答、不联网、不使用模型裁判。

#### 一、第一性原理：先明确自动化什么

**基石：**程序可以自动执行明确的规则，但不会因为能解析 JSON 就理解制度语义。

本课自动判断 F，C/G 则读取预先填写的人工分数。题目、材料与参考要点仍由评分者核验；脚本没有内置制度推理，也不使用关键词匹配冒充正确性评测。

| 输入信息 | 程序做什么 | 不做什么 |
|---|---|---|
| raw_output 原始回答字符串 | 解析 JSON 并校验字段与类型 | 不判断制度结论真假 |
| request_status | 区分 returned、timeout、error | 不实际发送请求或模拟真实耗时 |
| manual_scores 中的 C/G | 校验分值、计算汇总 | 不重新判断人工分数是否合理 |
| response_id、sample_id、category、config_id | 对齐逐题与类别/配置汇总 | 不因编号完整就证明实验公平 |

先自动化 F 的优势是便宜、透明、容易写测试；局限是它不能代替语义评分。适用前提是格式契约已定义清楚，人工 C/G 有可信依据。

#### 二、逆向检查：让程序跑通不等于评测正确

问题倒置：怎样把差系统自动统计成好系统？程序只处理成功请求、丢掉超时，或把“找到主管二字”当作完整正确答案。反推得到的要求是：保留所有计划运行记录，不用粗糙关键词规则代替语义标准。

反事实：如果题目要求主管和财务，但回答只有主管，即使 JSON 完全合法，F=1 也不代表 C=2。如果已有人工分数是错的，脚本会一致地汇总错误标注，不会自动纠正。

对立视角：开发者可能认为异常时继续跑完比停止更重要；评审则关心分母完整。模型回答格式错，可以记录后继续；记录文件本身损坏却无法确认这行属于哪道题时，继续忽略会污染统计。本课对后者明确报错并停止，由人修复输入后重跑，不把数据问题伪装成模型错误。

反向试错：引用编号存在就判 G=1 → 本课编号是否合法只属 F，语义引用由人工G检查；超时记C=0 → 保留状态，C/G/F为null；把待评分默认通过 → 展示待评分数，不发布最终任务通过率；重复样本当覆盖扩展 → 分别记录运行数和独立样本数；输出覆盖旧报告 → 用新文件名保存新报告。

- 长度限制：单条输入上限500字；多轮交互最大单条输入上限、多轮最大轮数、超长时的预处理规则（截断 / 摘要，需记录）
- 格式与编码：纯文本
- 上下文与工具权限：RAG 场景给10条检索片段

## 输出要求（模型输出契约）
- 结构格式：严格 JSON
- 纯净度：禁止寒暄前后缀，禁止把推理过程写入答案字段
- 内容与长度：允许输出「无法确定」
- 溯源：是否必须给出引用来源与定位
- 安全输出：拒答话术、禁止输出项、必要免责说明
- 采样与留痕：每题采样 n 次，全部原始输出留档
- 解析失败处理：解析失败计为 0 分并单独统计失败率（不得静默丢弃）

## 质量维度
- 答案正确性：最终答案与标准答案语义一致；不含格式与引用问题。指标为「准确率」
- 忠实性：答案中每条原子事实均可在给定上下文中找到支撑。不判断上下文本身是否真实，不判断答案整体对错。指标为「幻觉率」
- 运行质量：回答问题的平均时长。指标为「平均回答耗时」

## 实验设置
- 采样次数 n、温度、随机种子、并发数、单请求超时、失败重试策略
- 硬件 / 服务环境、调用配额、日志留存位置与保留期

## 整体设计思路
作为一个内部使用的答疑助手，正确性和耗时是第一优先级，所以在质量维度上将这三个作为了主要评分参考的维度。

### A3. 错误归因

题目：上海正式员工问入职两个月今年有多少年假、现在能否申请；助手答10天且可直接申请，HR确认错误。至少五可能原因及区分证据，事实/推测分开。

### A5. 方法选择

题目：给规则、人工、模型裁判各设计子任务，解释适用、风险、补救及能否替代。

原始答案：

```markdown
1. 规则评分：
  - 评什么：计算年假天数，评估计算准确性
  - why：计算方法固定，有稳定的输入输出
  - 风险和预防：风险主要是边界场景未覆盖，通过输出未覆盖标识，由人工补充逻辑。

2. 人工评分：
  - 评什么：模型输出是否清晰好理解，评估输出信息可读性
  - why：比较主观，没有明确的定义，需要人工介入模拟不同工作背景的用户
  - 风险和预防：不同人的主观理解不同，需要有统一的评判标准

3. 模型裁判：
  - 评什么：验证输出格式，评估输出是否符合要求
  - why：有明确的要求，可以通过提示词做简单判断
  - 风险和预防：暂时想不到

我理解不能完全互相替代。规则评分可以用模型裁判，但是在这种明确的规则下比较浪费资源。模型裁判也可以用规则评分替换，但是对于输出格式的校验需要写大量的校验规则，不如模型裁判高效。人工评分部分由于涉及主观，如果用模型裁判替代，也需要通过提示词让模型可以模拟站在不同工作背景下的员工视角，需要整体考虑成本和roi。
```

批改：15/20。三个方法技术可行，原评分未要求唯一最优，不因格式用裁判就把匹配点全部扣掉。人工主观差异与统一标准对应风险，得到相应分数。未充分比较可复现性，也没有裁判偏差。明确JSON通常解析器＋Schema便宜可复现；LLM适合难穷举的语义但需人工校准。模拟员工视角不能直接代表真实用户体验。

"""第五课：离线读取回答、校验格式、合并人工分数并汇总。

python3 lesson05_evaluator.py
python3 lesson05_evaluator.py --self-test

不联网、不执行模型回答、不自动判断语义，不覆盖已有输出文件。

import argparse
import hashlib
import json
from pathlib import Path


RUBRIC_VERSION = "lesson02-clarified-v1"
ALLOWED_EVIDENCE = {"R1", "R2"}

# 人工构造的教学结果及人工标注，不是模型实测成绩。
# 每条表示一次已经完成尝试的计划运行；所有计划项必须在输入中出现。
DEMO_RECORDS = [

        "request_status": "returned",

        "error": "教学模拟超时，无完整回答", "manual_scores": {"C": None, "G": None},

def reject_constant(value):
    raise ValueError(f"不是标准JSON常量: {value}")


def unique_object(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise ValueError(f"重复JSON字段: {key}")
        result[key] = value
    return result


def parse_json(text):
    return json.loads(text, object_pairs_hook=unique_object,
                      parse_constant=reject_constant)


def check_format(raw_output):
    """只评F；引用是否支持内容不在这个函数内判断。"""
    try:
        obj = parse_json(raw_output)
    except (ValueError, TypeError) as exc:
        return 0, f"JSON解析失败: {exc}"
    if not isinstance(obj, dict) or set(obj) != {"answer", "evidence"}:
        return 0, "必须是恰含answer和evidence的JSON对象"
    if not isinstance(obj["answer"], str) or not obj["answer"].strip():
        return 0, "answer必须是非空字符串"
    evidence = obj["evidence"]
    if not isinstance(evidence, list):
        return 0, "evidence必须是数组"
    if any(not isinstance(item, str) or item not in ALLOWED_EVIDENCE
           for item in evidence):
        return 0, "引用编号必须是R1或R2"
    return 1, "符合本课格式契约；不代表语义或引用正确"


def validate_records(records):
    """数据记录损坏时停止，不能把它当成模型失败或静默删除。"""
    seen = set()
    for index, record in enumerate(records, 1):
        if not isinstance(record, dict):
            raise ValueError(f"记录{index}: 必须是对象")
        for key in ("response_id", "sample_id", "category", "config_id"):
            if not isinstance(record.get(key), str) or not record[key].strip():
                raise ValueError(f"记录{index}: 缺少有效{key}")
        if record["response_id"] in seen:
            raise ValueError(f"记录{index}: response_id重复")
        seen.add(record["response_id"])
        if type(record.get("repeat")) is not int or record["repeat"] < 1:
            raise ValueError(f"记录{index}: repeat必须是正整数")
        status = record.get("request_status")
        if status not in {"returned", "timeout", "error"}:
            raise ValueError(f"记录{index}: 请求状态不合法")
        if "raw_output" not in record or "error" not in record:
            raise ValueError(f"记录{index}: 缺少raw_output或error")
        if status == "returned" and not isinstance(record["raw_output"], str):
            raise ValueError(f"记录{index}: returned必须保留文本原文")
        if record["raw_output"] is not None and not isinstance(record["raw_output"], str):
            raise ValueError(f"记录{index}: raw_output只能是字符串或null")
        scores = record.get("manual_scores")
        if not isinstance(scores, dict) or set(scores) != {"C", "G"}:
            raise ValueError(f"记录{index}: manual_scores必须包含C和G")
        for key, allowed in (("C", {0, 1, 2}), ("G", {0, 1})):
            value = scores[key]
            if value is not None and (type(value) is not int or value not in allowed):
                raise ValueError(f"记录{index}: {key}分数不合法")
            if status != "returned" and value is not None:
                raise ValueError(f"记录{index}: 未完整返回时C/G应为null")


def score_records(records):
    validate_records(records)
    scored = []
    for record in records:
        returned = record["request_status"] == "returned"
        F, reason = check_format(record["raw_output"]) if returned else (
            None, "没有完整回答，F不适用")
        C, G = record["manual_scores"]["C"], record["manual_scores"]["G"]
        task_pass = (C == 2 and G == 1 and F == 1) if returned else False
        if returned and (C is None or G is None):
            task_pass = None  # 待人工评分，不冒充语义错误。
        scored.append({
            **record, "scores": {"C": C, "G": G, "F": F},
            "format_reason": reason, "task_pass": task_pass,
            "rubric_version": RUBRIC_VERSION,
            "semantic_evaluator": "预先填写的人工标注；脚本不判断C/G",
        })
    return scored


def fraction(numerator, denominator):
    return {"numerator": numerator, "denominator": denominator,
            "rate": numerator / denominator if denominator else None}


def summarize(rows):
    planned = len(rows)
    returned = [r for r in rows if r["request_status"] == "returned"]
    C_known = [r for r in returned if r["scores"]["C"] is not None]
    G_known = [r for r in returned if r["scores"]["G"] is not None]
    pending = sum(r["task_pass"] is None for r in rows)
    passed = sum(r["task_pass"] is True for r in rows)
    return {
        "recorded_planned_runs": planned,
        "unique_samples": len({r["sample_id"] for r in rows}),
        "pending_semantic_reviews": pending,
        "returned_rate": fraction(len(returned), planned),
        "C_evaluation_coverage": fraction(len(C_known), len(returned)),
        "C_full_correct_rate_on_reviewed": fraction(
            sum(r["scores"]["C"] == 2 for r in C_known), len(C_known)),
        "G_evaluation_coverage": fraction(len(G_known), len(returned)),
        "G_pass_rate_on_reviewed": fraction(
            sum(r["scores"]["G"] == 1 for r in G_known), len(G_known)),
        "F_pass_rate_on_returned": fraction(
            sum(r["scores"]["F"] == 1 for r in returned), len(returned)),
        "confirmed_pass_lower_bound": fraction(passed, planned),
        "final_task_pass_rate": fraction(passed, planned) if not pending else None,
    }


def evaluate(records):
    rows = score_records(records)
    groups = {}
    configs = {}
    for row in rows:
        groups.setdefault(row["category"], []).append(row)
        configs.setdefault(row["config_id"], []).append(row)
    return {
        "summary": summarize(rows),
        "by_category": {name: summarize(group) for name, group in groups.items()},
        "by_config": {name: summarize(group) for name, group in configs.items()},
        "results": rows,
    }


def load_jsonl(path):
    records = []
    with path.open(encoding="utf-8") as handle:
        for line_number, line in enumerate(handle, 1):
            if not line.strip():
                continue
            try:
                records.append(parse_json(line))
            except ValueError as exc:
                raise ValueError(f"输入第{line_number}行损坏: {exc}") from exc
    return records


def self_test():
    report = evaluate(DEMO_RECORDS)
    summary = report["summary"]
    assert summary["returned_rate"]["rate"] == 3 / 4
    assert summary["C_full_correct_rate_on_reviewed"]["rate"] == 2 / 3
    assert summary["F_pass_rate_on_returned"]["rate"] == 2 / 3
    assert summary["final_task_pass_rate"]["rate"] == 1 / 4
    assert report["results"][3]["scores"] == {"C": None, "G": None, "F": None}
    assert report["results"][2]["scores"] == {"C": 2, "G": 1, "F": 0}
    assert evaluate([])["summary"]["returned_rate"]["rate"] is None
    assert evaluate([DEMO_RECORDS[3]])["summary"]["final_task_pass_rate"]["rate"] == 0
    pending = {**DEMO_RECORDS[0], "manual_scores": {"C": None, "G": None}}
    assert evaluate([pending])["summary"]["final_task_pass_rate"] is None
    assert evaluate([pending])["results"][0]["task_pass"] is None
    valid = '{"answer":"无法确定。","evidence":[]}'
    assert check_format(valid)[0] == 1
    invalid = ["不是JSON", "```json\n" + valid + "\n```", "[]",
               '{"answer":"","evidence":[]}',
               '{"answer":"a","evidence":"R1"}',
               '{"answer":"a","evidence":["R9"]}',
               '{"answer":"a","evidence":[],"extra":1}',
               '{"answer":"a","answer":"b","evidence":[]}',
               '{"answer":NaN,"evidence":[]}']
    for raw in invalid:
        assert check_format(raw)[0] == 0
    try:
        validate_records([DEMO_RECORDS[0], DEMO_RECORDS[0]])
    except ValueError:
        pass
    else:
        raise AssertionError("重复结果编号应被拒绝")
    print("测试通过：分母、超时、待评分、空集合、格式边界及重复编号。")


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--input", type=Path, help="已记录的教学结果JSONL")
    parser.add_argument("--output", type=Path, help="新报告JSON路径，不覆盖已有文件")
    parser.add_argument("--self-test", action="store_true")
    args = parser.parse_args()
    if args.self_test:
        self_test()
        return
    try:
        records = load_jsonl(args.input) if args.input else DEMO_RECORDS
        report = evaluate(records)
        report["source"] = "用户提供的结果文件" if args.input else "人工教学模拟，非模型实测"
        report["script_sha256"] = hashlib.sha256(Path(__file__).read_bytes()).hexdigest()
        if args.input:
            report["input_sha256"] = hashlib.sha256(args.input.read_bytes()).hexdigest()
        text = json.dumps(report, ensure_ascii=False, indent=2, allow_nan=False)
        if args.output:
            with args.output.open("x", encoding="utf-8") as handle:
                handle.write(text + "\n")
            print(f"已保存新报告: {args.output}")
        else:
            print(text)
    except (ValueError, OSError) as exc:
        parser.exit(1, f"评测未完成: {exc}\n")


if __name__ == "__main__":
    main()
